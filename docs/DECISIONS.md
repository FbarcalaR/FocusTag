# FocusTag — Decision Record

Each entry has a one-line **decision** and a one-line **rationale**. When an entry overrides the original brief, it says so. Entries are referenced from `PLAN.md` as `D-xx`.

## Platform & build

| ID | Decision | Rationale |
|----|----------|-----------|
| D-01 | **compileSdk = targetSdk = 37** (Android 17, the latest stable platform in the SDK repository on 2026-10-06), **minSdk = 33**. *Correction (T1):* the SDK package is `platforms;android-37.0` (API 37 ships only as minor levels 37.0/37.1/37.2), so `app/build.gradle.kts` uses the AGP 9 DSL `compileSdk { version = release(37) }` (likewise `targetSdk`/`minSdk`); plain `compileSdk = 37` would look for a non-existent `android-37`. | The brief asks for the latest stable SDK. The Pixel 10a runs Android 16 (API 36), and a higher target runs fine on it. Android 17 behaviour changes are recorded in D-07. |
| D-02 | **AGP 9.4.1, Gradle wrapper 9.8.0** (AGP 9.4 needs Gradle ≥ 9.6.0), AGP built-in Kotlin (no `kotlin-android` plugin), with dependency versions in `gradle/libs.versions.toml`. **Kotlin is pinned to 2.3.21**, not the newer 2.4.20: KSP 2.3.12 is built on Kotlin 2.3.20, Hilt/Dagger 2.60.1 on kotlin-bom 2.3.21 and kotlinx-serialization 1.11 on stdlib 2.3.20, so the whole toolchain stays on one Kotlin line. Revisit when KSP and Dagger ship 2.4-based releases. | These are the current stable releases. A single version catalog keeps upgrades in one place. Lint's `NewerVersionAvailable` warning for the Kotlin plugins is expected. |
| D-03 | **Single Gradle module `:app`**, with the layers as packages: `nfc`, `focus`, `blocker`, `system`, `ui`, plus `di`. | A personal app with one screen pair doesn't need multi-module build overhead. Package boundaries plus file ownership give enough separation for parallel work. |
| D-04 | **Hilt (with KSP)** for dependency injection. Fallback: manual DI via an `AppContainer` if Hilt doesn't support AGP 9 built-in Kotlin when T1 runs. *Confirmed (T1):* Hilt 2.60.1's Gradle plugin requires AGP ≥ 9.0 and KSP 2.3.12 supports built-in Kotlin, so the fallback is not needed. | Hilt injects directly into `AccessibilityService`, `BroadcastReceiver`, `Activity` and `ViewModel`, and `@TestInstallIn` / `@BindValue` make it easy to swap in fakes under Robolectric. |
| D-05 | **All automated tests run on the JVM** (JUnit 4 + Robolectric + Compose UI tests under Robolectric) via `./gradlew test`. There are no required instrumented tests. | The CI container has no emulator. Robolectric runs both Compose UI tests and Android component tests there. |
| D-06 | `scripts/setup-android-sdk.sh` (idempotent; `ANDROID_HOME`, else `/opt/android-sdk` if present, else `~/android-sdk`) installs cmdline-tools, `platforms;android-37.0`, `build-tools;37.0.0` and `platform-tools`, then writes `local.properties`. A GitHub Actions workflow runs `assembleDebug lint test`. | The cloud container has no Android SDK, and the three commands have to be reproducible anywhere. |
| D-07 | **Android 17 (API 37) target behaviour changes** reviewed: (1) static final fields can no longer be modified via reflection; (2) new lock-free `MessageQueue` breaks reflection on its internals; (3) background-activity-launch hardening extends to `IntentSender`, and `MODE_BACKGROUND_ACTIVITY_START_ALLOWED` is deprecated in favour of `…_ALLOW_IF_VISIBLE`; (4) the large-screen orientation/resizability opt-out is removed. **No impact:** we use none of these reflections; our only `PendingIntent` is the notification's user-tapped content intent (T2 must not opt into background activity starts); the blocker launches from an accessibility service; the app is phone-only. | D-08 | **Robolectric 4.17 on SDK 37 under JDK 21** needs `--add-exports=java.base/jdk.internal.access=ALL-UNNAMED` and `--add-opens=java.base/java.io=ALL-UNNAMED` on the unit-test JVM, and **Espresso 3.7.0** (older Espresso calls `InputManager.getInstance()`, which API 37 removed). Both are set in `app/build.gradle.kts` / the catalog. | Without them every Robolectric test fails at sandbox setup or at the first Compose interaction. |

## NFC

| ID | Decision | Rationale |
|----|----------|-----------|
| D-10 | Tag payload is an NDEF message containing (1) the URI record `focustag://toggle/<tagId>`, where `tagId` is a random UUID generated at pairing, and (2) an Android Application Record (AAR) for our package. | The URI makes the tag self-describing. The AAR routes the scan straight to our app and avoids a chooser dialog. |
| D-11 | Pairing stores `{role, tagId, uidHex}` per tag (A = desk/activate, B = living room/deactivate) in a DataStore owned by `nfc`. | We need both values to validate a scan (D-12). |
| D-12 | **A scan is valid only if** the URI parses as `focustag://toggle/<tagId>`, *and* that `tagId` belongs to a paired role, *and* the tag's hardware UID equals the stored UID for that role. Every other scan is silently ignored. | This rejects unknown tags, copied URIs on other tags, and stale tags left over from a re-pair. |
| D-13 | **Background scans:** a manifest `NDEF_DISCOVERED` filter (scheme `focustag`, host `toggle`) on a translucent, `excludeFromRecents`, `noHistory` **`NfcTriggerActivity`**. It validates the scan, calls `FocusController`, shows a short toast, and finishes. | Scans work when the app is closed and the phone is unlocked, as the brief requires, without pulling the full UI to the front. |
| D-14 | **Pairing on the Setup screen uses `NfcAdapter.enableReaderMode`** instead of `enableForegroundDispatch`. **This overrides the brief.** | Like foreground dispatch, reader mode gives the open screen exclusive tag access, so a pairing scan never triggers the manifest filter and toggles focus by accident. It also delivers the `Tag` through a callback, so pairing needs no `onNewIntent` plumbing in `MainActivity` and can live entirely in `ui/setup` and `nfc`. |
| D-15 | Hardware access goes through `NfcGateway` (is NFC available/enabled, enable/disable reader mode, write NDEF) and `ScannedTag(uidHex, ndefUris)`. Tests use `FakeNfcGateway`. | The brief requires a fakeable interface. Keeping `android.nfc.Tag` out of the domain keeps validation pure. |
| D-16 | Recommended tags: **NTAG213/215/216**. The README explains how to use them. | They have fixed 7-byte UIDs and are writable NDEF Forum Type 2 tags. Tags with randomised UIDs would break D-12. |

## App blocking

| ID | Decision | Rationale |
|----|----------|-----------|
| D-20 | **Chosen approach: `AccessibilityService`** listening for `TYPE_WINDOW_STATE_CHANGED` (plus `TYPE_WINDOWS_CHANGED` for split-screen and picture-in-picture). It launches `BlockingActivity` (`NEW_TASK`, own `taskAffinity`, `excludeFromRecents`), and falls back to `performGlobalAction(GLOBAL_ACTION_HOME)`. | It's event-driven, so blocking is instant with no polling battery cost. A system-bound accessibility service is also exempt from background-activity-launch restrictions, so the blocking screen reliably appears. |
| D-21 | **Rejected: UsageStats polling.** | It needs a 0.5–1 s polling loop in a foreground service, so a blocked app can show for up to a second. It costs battery, needs `PACKAGE_USAGE_STATS`, and on Android 14+ background activity launches from a plain service are blocked. Usage access is therefore **not** requested. |
| D-22 | Blocking decisions live in a pure `BlockDecider(focusActive, blockedSet, packageName, alwaysAllowed)`. **Always allowed:** our own app, SystemUI, the default launcher, the default dialer/emergency apps, IMEs and Settings. | Pure logic is easy to unit-test. Never blocking the phone, the launcher or our own UI avoids locking the user out. |
| D-23 | When Focus starts, the service checks the current foreground window (`rootInActiveWindow`) right away. | Otherwise a blocked app that is already open when Tag A is scanned would stay usable until the next window change. |
| D-24 | The installed-apps list uses a `<queries>` entry for `MAIN`/`LAUNCHER` intents instead of `QUERY_ALL_PACKAGES`. | Only launchable apps need blocking, and this is the narrower permission. |
| D-25 | Sideload caveat: Android 13+ marks the Accessibility toggle of sideloaded apps as a **restricted setting**. The Setup row deep-links to App info, where the user must open ⋮ → *Allow restricted settings* first. | Without this the user can't enable the service at all. |

## DND & grayscale

| ID | Decision | Rationale |
|----|----------|-----------|
| D-30 | **Primary approach: one `AutomaticZenRule`** (type `TYPE_OTHER`, owner/configuration activity = `MainActivity`, interruption filter `PRIORITY` with a policy that allows nothing, plus `ZenDeviceEffects.Builder().setShouldDisplayGrayscale(true)`). It is created with `NotificationManager.addAutomaticZenRule` and toggled with `setAutomaticZenRuleState(id, Condition(..., STATE_TRUE/FALSE, SOURCE_USER_ACTION))`. | One Android 15+ "mode" handles both DND and grayscale. `setShouldDisplayGrayscale` is public (non-SystemApi) API 35, and third-party apps already use it on Android 15/16 (e.g. PlugNap). |
| D-31 | **Correction to the brief:** this approach is not permission-free. `addAutomaticZenRule` requires **notification policy access** (the user grants "Do Not Disturb access" in Settings). It does *not* need `WRITE_SECURE_SETTINGS`. | Documented requirement of the API. The DND permission row is therefore required. |
| D-32 | `setInterruptionFilter` is **not used** for DND. | Apps targeting 35+ already get an *implicit* `AutomaticZenRule` from that call, so it offers no advantage over an explicit rule, and it can't apply grayscale. |
| D-33 | **Fallback grayscale** (optional, off by default): `Settings.Secure.accessibility_display_daltonizer_enabled=1` and `accessibility_display_daltonizer=0`, only if `WRITE_SECURE_SETTINGS` is granted. The previous values are saved and restored on exit. Setup shows the exact command: `adb shell pm grant <applicationId> android.permission.WRITE_SECURE_SETTINGS`. | This covers the case where the manual device check shows that zen-rule grayscale doesn't render on the Pixel, or where the user changed the mode's effects in Settings. |
| D-34 | **Re-assertion:** in FOCUS, the engine listens for `ACTION_AUTOMATIC_ZEN_RULE_STATUS_CHANGED` / `ACTION_INTERRUPTION_FILTER_CHANGED` and checks `getAutomaticZenRuleState(id)` on app start and on boot. If the rule was switched off by the user (Quick Settings or Modes page), the engine sends FALSE then TRUE to re-activate it. | Users *can* turn a mode off from Quick Settings, and the system can't prevent that. Re-asserting keeps Focus "sticky". Whether FALSE→TRUE overrides a manual user override on Android 16 is a **manual device check** (MC-07). |
| D-35 | If the rule is deleted or its access is revoked, the engine re-creates the rule when it next has access. The Status screen warns while access is missing. | Revoking a permission mid-session must not crash the app or silently drop Focus state. |

## State, persistence & lifecycle

| ID | Decision | Rationale |
|----|----------|-----------|
| D-40 | **Pure state machine:** `transition(state, TagRole) -> Transition(newState, changed)`. FREE+A → FOCUS, FOCUS+B → FREE, everything else is a no-op (`changed = false`). | Idempotent and trivially exhaustive to test. Double scans become no-ops. |
| D-41 | The **single source of truth** is `FocusStateStore` (Preferences DataStore, owned by `focus`): `mode`, `sessionStartEpochMs`, and a per-day map of completed focus milliseconds (last 30 days). Effects are always *derived* from the stored state by `FocusEngine.reconcile()`. | After a process kill or reboot, the app reconciles to the stored state instead of trusting in-memory flags. |
| D-42 | Times use wall-clock `Clock` (injectable). "Today" uses the device's local `ZoneId`. A session that crosses midnight is split between days when it ends, and while live. | Wall-clock time survives reboots, unlike `elapsedRealtime`. An injectable clock makes the tests deterministic. |
| D-43 | `BootReceiver` (`BOOT_COMPLETED` and `MY_PACKAGE_REPLACED`; DataStore lives in credential-encrypted storage, so `LOCKED_BOOT_COMPLETED` is not used) calls `FocusEngine.reconcile()` via `goAsync()`. `FocusTagApp.onCreate` also runs reconcile through a Hilt multibound `Set<AppStartHook>`. | Covers reboots, app updates and process restarts. The multibinding lets `focus` contribute the hook without editing T1's file. |
| D-44 | While in FOCUS, an ongoing, low-importance **"Focus active" notification** is shown. It has no actions and opens the Status screen when tapped. | Visible state, and it's the reason the notification permission is in the checklist. |
| D-45 | **No in-app exit:** the UI has no button that changes the mode. While in FOCUS, the Setup screen is read-only for tag reset/re-pair and for *removing* apps from the block list (adding is allowed). | Otherwise unpairing a tag or emptying the block list would be an escape hatch from inside the app. |
| D-46 | Out-of-app escapes (disabling the accessibility service, revoking DND access, uninstalling) **can't be prevented** without device-owner mode, which is out of scope. They are detected and shown in the Status warning banner. | Honest limitation for a sideloaded personal app. |
| D-47 | Battery optimisation exemption is requested with `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. This is allowed because the app is sideloaded with no Play policy. | Keeps the receivers and the re-assertion reliable under Doze. |

## Process

| ID | Decision | Rationale |
|----|----------|-----------|
| D-50 | **T1 freezes the cross-layer contracts** (interfaces + DTOs in `<layer>/Contracts.kt`) and ships a placeholder implementation plus a Hilt binding module per layer. Each layer task replaces only its own placeholder. Changing a contract needs approval from the orchestrator. | Every task branch then compiles and passes the full build on its own, so parallel groups never wait on each other's bindings. |
| D-51 | T1 declares **all manifest components** (activities, service, receiver, intent filters, permissions, `<queries>`) and every `res/xml` config, pointing at stub classes. Resources are split per layer (`strings_<layer>.xml`). | The manifest and `strings.xml` would otherwise be merge-conflict hot spots shared by every task. |
| D-52 | Integration branch = `claude/focustag-nfc-android-d75mvp` (this plays the role of "main" in the brief). Task branches are **local** worktrees (`task/Tn-*`) that are merged in and never pushed. | The session can only push to the designated branch. |
